Task 1: Drawing Single-Color Triangles

For this task, I implemented simple triangle rasterization. I did this by first finding the maximum and minimum y and x values of the triangle, in order to have a smaller range of pixels to loop through. I also clamped these values to the screen. I also used the Vector2D object in order to make the 3 sides of the triangle their own vector. Then, for each pixel in that range, I sampled at the pixel's center (x+ 0.5, y + 0.5), and called a helper function called "inside" and passed in the points and vectors (sides) of the triangle, as well as the current point. The purpose of this function was to determine if the point was inside the triangle. If the inside function returned "true", I used the fill_pixel function to color that point the given color value. The inside function ensured that as we walk from point A to point B, that the cross product between the vector AB and the vector AP (p being the point we're checking) is always positive for every edge (meaning on the left side of the line, if we're walking counter clockwise), or always negative on every edge (if we happen to be walking clockwise). Accepting either case means the triangle draws regardless of winding order, and I counted a cross product of 0 as inside so points exactly on an edge get drawn. If this was true, meaning the point is inside the triangle, I returned true from this helper function. After implementing this rasterization, many svgs were filled with color.

My algorithm is no worse than one that checks each sample within the bounding box, because it only loops through the pixels within the bounding box. The whole triangle is inside it since it uses the max and min x and y values.

As you can see here, the images are filled in with color. The last image shows the tip of a triangle which is experiencing aliasing. There are gaps and jagged edges as I zoomed into the picture. This is because no anti-aliasing methods, such as supersampling, were done yet.

Task 2: Antialiasing by Supersampling

Supersampling is a very useful technique becauase getting a sample at each pixel only once leads to aliasing. The edges start to look jagged, creating "jaggies", and very thing parts of shapes like triangles can start to break or not show. What supersampling does is takes more than one sample at each pixel and averages them, so that smoothing happens and edges start to look smoother. To make this change, we changed the sample_buffer so that it stores sample_rate number of colors for each pixel instead of one. The vector is also sized to width * height * sample_rate, to make sure there is enough space for every sample. We also edited set_sample_rate and set_framebuffer_target to resize the buffer to the capacity needed by the sample_rate at that time. In rasterize_triangle, we made sure to scale the box and vertices of the triangle by sqrt(sample_rate) so that the rasterization happened with these subsamples. Then, it was the same process of checking if a subsample is inside the triangle. Finally, resolve_to_framebuffer takes all of the samples for each pixel and averages them before writing to the frambuffer. This is what antialiases the triangle and creates smoother edges.

Task 4: Barycentric coordinates

Using barycentric coordinates allows you to express any point inside the triangle as a blend of the three vertices of the triangle. Every point gets three weights (α, β, γ) which always sum to 1. A weight is larger if the point is closer to that vertex. For example, a vertex has 1 for its corresponding weight and 0 for the other 2 weights. This is useful because these weights can be used to blend values represented at the vertex, such as color.

In this triangle, the bottom vertex stores red, the top-left vertex stores blue, and the top-right vertex stores green. Each corner is that pure color becasue its expressing only the color associated with that weight, but as you move a point within the triangle it starts to blend these colors, creating the gradient shown.

Task 5: "Pixel sampling" for texture mapping

Pixel sampling is how we choose a screen pixel's color by looking up the matching spot on a texture image. For each sample inside the triangle, I computed its barycentric weights from the screen-space vertices and used them to blend the vertices' texture coordinates into a (u, v) position. I then scaled (u, v) by the texture's size to get texel coordinates and sampled a color there, which I stored in the sample buffer. Nearest sampling takes the color of the single texel the point lands in, which is fast but looks blocky when the texture is magnified. Bilinear sampling blends the four surrounding texels based on how close the point is to each, so colors transition smoothly between texels.

Nearest sampling at 1 sample per pixel shows hard, blocky steps between colors, while bilinear at 1 sample per pixel blends neighboring texels and gives smoother transitions. At 16 samples per pixel, both methods get smoother edges on the blue ring, but nearest still looks harsher inside the texture. The two methods differ most when the texture is magnified, because nearest repeats one texel across many pixels while bilinear blends smoothly between them.
